## 1. 本次偏差及责任

此前助手未经完成定稿与流程冻结就开展了50条试运行，并另建 word-page-v10 模板：简化了既有学习义项和例句、改变完整词典展开方式、把实际词义按钮改成通用导航、未复用已有历史内容、在阅读正文展示生产审核提示。与 V10 上位规范“旧前部默认不动、现有九模块增量修改”不符。

此前技术验证只证明候选能够渲染及部分交互正常，不能证明遵循旧版和规划。尤其不能用模块数量仍为九个代替模块内容、视觉、交互和接口的保留检查。

50条旧试样保留为过程记录与可重新审查的材料；**不是已认可的V10基准、校准集或可继续生产的起点**。已有文档提交、50条文字审阅及页面测试，都不补足此前缺失的启动条件。不得再将该过程描述为“按用户要求的顺序完成”。

## 2. 四个必须分开的状态

1. **方案草稿**：把产品、页面、内容、来源、生产与QA合同写全，列出具体保留和修改项。
2. **本地／云端对齐**：确认相同版本的文档、来源指针、决策和未决项一致。这只证明同步，不证明方案被认可。
3. **方案与流程冻结**：在具体版本获得用户审定后，形成冻结清单，锁定基准、模块差异、资料规则、生成规则、QA判据及失败处理；尚有影响运行的未决项时不能冒称冻结。
4. **试运行启动**：冻结之后，按用户明确确认的启动安排执行指定样本与批次。不得把“以后再试运行”或“文档已推送”自动解释成当前可启动。

当前仅进行第1、2步。尚无本次纠偏方案的用户审定记录、冻结编号或试运行启动记录；不得由助手自行填写为通过。

## 4. 冻结前必须写清的生产流程

| 阶段 | 输入 → 输出 | 进入下一阶段的必要证据 | 失败处理 |
| --- | --- | --- | --- |
| 输入盘点 | 原ID／上下文／原句 → 只读快照与选样清单 | 原库、原句指纹；选样理由与覆盖矩阵 | 缺原句／身份歧义先标缺口，不臆造 |
| 资料接入 | 明确来源版本 → 义项／专业依据与覆盖清单 | 可访问范围、许可、支持主张、失败记录 | 403不算接入；摘录不算完整词典；无依据不自动通过 |
| 场景定位 | 原句＋库存 → 当前义与限定条件 | 词／短语整体身份、目标词形、否定条件保真 | 未定位则停止肯定性解释 |
| Bridge | 当前义＋已核实锚点 → 联系、补充和边界 | 定位与联系策略分别记录；引用能支持具体解释 | 不可靠的历史和推导不生成 |
| 七步写作 | 原Prompt＋当前语境＋Practice → 自然连续分析 | 每维作用可检查；2–5原创工作表达附中文和使用条件 | 无意义套话、重复或错误英语退修 |
| 独立内容QA | 明确稿件与输入 → 逐项问题及审阅结论 | 审阅者、范围、输入指纹、稿件哈希 | 修订后原pass失效；不拿作者自评替代独立审核 |
| 页面适配QA | 已审内容＋冻结旧模板 → 候选页面 | 逐区保留检查、逐项规划追踪、视觉和交互证据 | 偏离旧版或规划即失败，即使页面能打开 |
| 候选封包 | 全部证据 → 版本清单、缺口和回滚指针 | 内容／视图／接口／流程分别版本化 | 半成品不标完成；技术通过不等于用户接受 |

每个阶段需说明由人工、助手还是已实现脚本负责。未实现的模型API、自动队列、自动重试、增量调度不能写成已有能力。具体样本规模、子批、修订上限、阻塞项是否占批次名额及最终停止条件必须随冻结版本写明；不能边运行边擅自改变。

## 5. QA必须覆盖三类对照

### A. 设计符合性：先回答“是不是我们要的版本”

- 逐区对照V9：顺序、展示／折叠、内容密度、词义按钮、来源、历史、Bridge返回链接、发音与导航。
- 逐条对照V10：每项要求写对应产物／验证证据／结论，不能只有笼统“符合规划”。
- 相同词、相同原句、相同屏幕宽度做旧版／候选对照；新增词另查资料覆盖，不用不同词掩盖模板变化。
- 任一未获批准的前部删减、全局主题重写或结构改变，判失败，回到方案层处理。
- 制作上述QA用的页面或样本也需等冻结后按已确认安排执行；当前只写检查方法，不继续生成试样。

### B. 内容正确性：不能只数段落和字段

- 精选义项是否来源明确、是否被场景义替代；词典库存覆盖和缺口是否真实。
- 原句否定／条件／时间／主体／承诺强度是否保留。
- 整体表达与单词义是否混用；补充义项是否有依据；类比、现代联系与历史是否区分。
- Bridge是否解释真实联系及边界，是否复用已有可靠材料。
- 七步是否各有作用、按词需要展开；共享Practice是否适用；英文邻居是否解释关联原因。
- 英文工作表达是否自然、可用且为原创标识；中文是否匹配；不能把教学构造冒充来源原话。
- 审核只覆盖文字时明确写“文字审核”；不能升级成完整包、学习效果或用户验收。

### C. 工程正确性：作为必要条件，不能替代A、B

- 原ID、原句、旧冻结产物、学习记录及备份兼容性。
- 输入／稿件／来源／Prompt／Practice变化后的审核失效。
- 重复运行、断点恢复、状态汇总及失败重试上限；无独立审核不能accepted。
- 三屏实际渲染、文字溢出／遮挡、折叠、锚点、返回、复制和发音无跳版。
- 页面锁与实际产物一致；按词加载；控制台错误、空壳模板及缺依赖检查。
- 真机、Safari、真实语音和学习效果未测时逐项写未测，不用模拟测试代替。

## 6. 冻结包应包含的文件与记录

1. 权威基准清单：旧页面、原内容、原Prompt、V10上位规范及提交／哈希。
2. 逐模块差异表：保留／允许改动／不得改动，分别锁定接口、内容、视图、生产流程版本。
3. 来源接入合同：逐来源能力、覆盖、许可、缺口与替代路径；不把“尽量接成熟资料”落成任意替换前部。
4. 生成合同：输入输出、义项定位、Bridge、七步、Practice、人工和自动职责。
5. QA矩阵：需求ID、检查方法、通过条件、失败条件、审阅角色和证据路径。
6. 运行合同：样本与批次、启动门、重试／阻塞／停止规则、成本记录与回滚。
7. 对齐回执：本地／云端确切文件版本与哈希，以及尚未决事项。
8. 用户审定记录与冻结编号：明确批准的是哪一版本；随后才按确认安排开始试运行。
