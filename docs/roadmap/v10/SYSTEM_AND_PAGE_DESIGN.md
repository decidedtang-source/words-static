# Words System V10：系统到页面的下一版设计

状态：`PLANNING_BASELINE_RECORDED / IMPLEMENTATION_NOT_STARTED / NOT_DEPLOYED`。规划版本 1，2026-11-16。基准见 [V9](../../baselines/WORD_SYSTEM_V9_20261116.md)。

## 1. 目标、范围与取舍

目标不是为 1,875 条记录生成同样长的七段文字，而是建立可复用的义项资源、忠实的原句定位、多路径 Bridge、七步原创分析和共享语言实践网络，并接回既有学习系统。

保留旧网页、九模块架构、静态构建、词条身份、搜索／复制／发音／学习记录。扩展内容系统而非另造网站。系统规划、页面规划、生产规划分别验收。

本次讨论已选择：以现有九模块作增量，而不是全面重写应用；按语境路由而不是强制从常用义推导；共享实践资料而不是每词复制整套流程。重新搭服务端会扩大迁移面；只批量润色五区则无法解决语用分析缺失，这两种都不作为本期路线。

## 2. 系统分层与权威

| 层 | 责任 | 不承担什么 |
|---|---|---|
| 原始材料层 | 现有词库、原句、Episode／文章／教学构造的身份与版本 | 不把未经核实的来源猜成真实工作记录 |
| 证据与义项层 | 可用许可范围内的来源、义项 ID、词性、短语、专业定义与依据 | 不把“完整”说成穷尽英语、也不把搜索索引当完整抓取 |
| 场景与连接层 | 精选学习义、当前用法定位、补充义项、Bridge | 不以学习优先级决定原句必须是什么意思 |
| 教学分析层 | 原始七步方法、三档深度、关联共享实践 | 不把流程常识冒充某词的固定语义 |
| 生产与治理层 | 输入快照、批次、审阅、修订、版本、成本、恢复 | 不以成功渲染／自评分代替内容正确性 |
| 阅读与学习层 | 九模块页面、查阅、背词、按需深读、未来迁移练习 | 不将已读等同掌握，不自动覆盖学习历史 |

产品实现和内容合同以本仓库为准；用户方法、跨会话路线和材料索引以 Context Hub Project 0003 为准。用户原 Prompt 优先于生产适配文案。Hub 不复制生产词库；产品仓不存私有邮件／访问凭据。

## 3. 主要实体与引用

保留每个原 `entryId`／card ID；不要用词头字符串替代学习身份。增加或适配以下逻辑实体，具体 JSON schema 在实施阶段以测试先行落地：

- LexicalEntry：单词、固定短语、组合型术语、交际块；类型可重叠。
- Sense：来源可追溯的义项；source ID 与本地 sense ID 分离；缺失或语境具体化不随意制造新义项。
- LearningSelection：从已验证义项挑选的学习视图，保存选择理由而非假频率。
- ContextUse：原句、上下文、否定／条件、目标 span、当前义项或组合解释、来源身份。
- Bridge：引用已确认语义锚点，保存关联类型与边界。
- Analysis：以 entry + context 为单位的七步内容，保留原句指纹、prompt 版本、深度、审阅状态。
- Practice：共享 Language Game，包含角色、典型问题、判断条件、常见但非必然的行动与回应。
- Release：只纳入验收内容的清单和版本锁，不改变既有学习事件 schema。

同一 entry 可有多个 ContextUse；同一词的不同语境不是自动共享一篇分析。1,875 是当前学习入口目标，不等于只有 1,875 个可分析语境；额外语境另计。

## 4. 共享语用网络

先从实际词库归纳约 20–30 个实践簇作为预算，不硬凑数量。可从问题评审、责任分配、需求澄清、变更与版本、测试验证、质量放行、供应交付、成本谈判、普通会议和日常协调开始。

每个 Practice 记录：典型情境；角色及权限差异；讨论目标；关键概念；自然追问；可接受回应；判断／证据条件；边界和反例；版本及来源。词条可连接多个 Practice，也可暂不连接。

English Neighbors 的边必须说明关系，例如 collocation、contrast、required-evidence、role、typical-follow-up、condition；关系是对当前实践的分析，不能伪装成语料统计频率。`owner → due date` 是行动项管理中的关联，不是同义或逻辑必然。

共享网络存一份，但每个词条必须仍有可独立阅读的 1–3 句本地应用说明；不能让学习者跳转几次才懂当前词。首次不需要图数据库、复杂可视化或大规模知识图谱服务。

## 5. 页面模块增量

- headword：继承 V9 发音及无障碍处理。
- source-preview：继续引用 scenario 原句，不生成另一份不同原文。
- navigation：继承连续纵向阅读和页内锚点；增加必要的七步入口，不强制 A/B 切换。
- dictionary：从“预留接口”发展为标明覆盖范围的义项库存；无资料显示真实缺口。
- learning：改为精选学习视图，未有统计依据时用“精选常用义项”，不叫“高频排名”。
- history：独立史源信息可选；不得成为所有 Bridge 的必经依赖。
- scenario：当前用法可指向常用列表之外的已验证义项或整体术语；保留原句限定。
- bridge：新增路由元数据与补充锚点说明；视觉保留普通段落，不展示编辑器内部状态词。
- analysis：以七步方法替换新版本的五区，不再强保留“先记住再联系”占一个深析区。七步是分析维度，不是七块等长卡片。

旧前部内容默认不动。新义项／锚点确有缺口时仅扩展新候选的对应模块并重审下游，不回写 V6–V9。既有九模块中的未受影响版本保持不变；shared theme 只有必要时才改。

## 6. 学习体验与后续系统路线

本期：优先全库内容可靠性、原句可定位、七步可读和按需深读。完整内容可生成并存储，不要求一次全展开。保留简明默认和深读路径，页面不在线反复调用模型。

后续独立规划：新词增量生产、用户纠错与内容补丁、共享网络检索、迁移练习和学习效果反馈。自动跨设备同步、账号／域名／后端架构继续属于独立设计议题；既有 private-domain 方案保留原状态，本规划不自动激活。

Episode、Scenario、实际工作或日常学习均可作为输入；按需读取 Google Drive，不为每词强制遍历所有材料。技术教学仍按“现实问题→中文概念→英文术语→工程语境→工作表达”。

## 7. 成功判准

普通义未覆盖偏门用法时能够补充并解释；学习者能说清联系的范围及不能推导出的部分；能在新句子中辨认概念与行动差异。全量覆盖、用户试读、自动测试、发布四种状态分开记录。
