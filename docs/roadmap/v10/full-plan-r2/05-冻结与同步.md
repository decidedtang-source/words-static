# 分模块冻结、本地云端同步与发布边界

## 1. 当前状态和不同的门

当前是`PLAN_REVIEW_READY / NOT_FROZEN / TRIAL_ON_HOLD`。完整方案交付不自动改变暂停状态。

| 门 | 需要的具体记录 | 通过后允许 | 不能推定 |
| --- | --- | --- | --- |
| F0 文档齐备 | 本R2全部文件、模块／需求／QA关联和文档校验 | 供用户审阅、同步文档 | 不能运行或声称已冻结 |
| F1 文档对齐 | 产品main不可变提交、Hub登记、本地审阅副本及SHA | 确认大家读同一稿 | 不等于用户批准 |
| F2 方案审定 | 用户针对具体planVersion／文档哈希的批准与范围 | 将该版本登记为已审定 | 不沿用旧试样／旧同步回执当批准 |
| F3 流程冻结 | freezeId、批准指针、基准、接口／模块差异、来源、生成、QA、批次和失败参数 | 执行冻结合同内已明确获准的准备／实施 | 不擅自启动超范围生成或部署 |
| F4 实施／试运行启动 | 明确启动范围、entry/context清单、角色、费用边界、暂停解除记录 | 按约定实施或运行指定批次 | “以后试跑”不能默认现在启动 |
| F5 候选接受／发布 | 对具体candidateLock的验收、发布目标及单独授权 | 在授权范围发布并回读 | 不扩大到100／1875、日更或Podcast |

用户同一条明确指令可同时覆盖F2–F4的部分事项，记录其具体范围即可，无需反复索要同一批准；缺失的部分不能由助手代填。仅说“完成方案”只授权本轮规划。

## 2. 方案冻结包清单

freezeId采用 `v10-plan-r2-<日期>-<序号>`，在F2前保持null，不能预先写成已冻结。

冻结包必须包括：

1. 本R2所有文件及SHA；原Prompt SHA；V9源commit/tree和旧页面／模块锁。
2. 九模块保留／变更／禁止项及具体影响文件；共享主题例外清单（默认空）。
3. 数据接口、身份、字段归属、依赖／失效和兼容适配。
4. 来源接入规则、已知能力限制、主张级证据标准与失败回退；未签供应商不填已接入。
5. 写作／审阅／封包职责、状态机、指纹、恢复、修订计数和成本规则。
6. Q矩阵、严重性、停批条件、证据格式、用户试读和未测项规则。
7. 拟运行参数与样本覆盖，实际ID和启动范围在F4登记；未填不得生成。
8. 用户审定记录、尚有分歧的清单。影响执行的分歧未解决，F3不通过；资料逐词取得属于未来执行证据，不能伪填现成事实。

## 3. 模块独立版本与锁

每模块分别记录interfaceVersion、contentVersion、viewVersion、processVersion；共享theme/shell/adapter/sourceRegistry独立版本和哈希。版本变化以实际内容为准，不统一给所有模块升版本制造“新系统”。

| 改动 | 应改版本／需重验 |
| --- | --- |
| 只改IPA或某义例句 | 对应content；来源映射及受影响内容QA |
| 只改发音显示／事件 | M01 view及需要的process；布局、可访问性、音频生命周期 |
| 更改接口字段／语义 | interface和适配；消费者兼容，通常主版本变更 |
| 更改生成规则或资料准入 | process；受影响输入指纹和内容审核 |
| 新七步替代旧五区 | M09 interface/view/process/content；明确迁移，不改旧V9 |
| 增加Bridge路由 | M08 interface/process；只有必要时改view，源句与锚点重审 |
| 改共享主题／壳 | shared版本；所有模块设计与交互QA，须先登记原因 |

原M01视图1.1.0及不受影响模块的旧版本保留，除非确有批准变更。候选release用新名称，绝不覆盖 `public/previews/word-layout-v6…v9`。新文件清单、输出哈希和实际模块版本进入candidateLock，旧accepted产物使用不可变revision保留。

## 4. 本地与云端同步的具体过程

产品仓持有完整方案和接口规范；Hub Project0003持有当前状态、决策和不可变产品链接；本地审阅副本提供同一套相对链接可读文档。Hub不复制原始生产词库。

先验证文档→提交产品文档（标`[skip ci]`，不部署页面）→确认remote main与具体文件→更新Hub索引／状态／产品SHA→提交Hub→回读Hub→复制规范字节至本地审阅目录→逐文件SHA比对→写同步回执。发生远端并行变更先读差异再正常合并，禁止force覆盖。

回执区分planVersion、productCommit、hubCommit、fileHashes、checkedAt、documentStatus、ownerApproval、freezeId、trialAuthorization。后3项没有记录时写null／not_granted，不能由“文件相同”变成true。manifest不包含自身哈希以免递归；其自身哈希在外部回执记录。

Windows换行差异按规范UTF-8/LF文件进行明确核对；原字节资料和历史冻结不重排。若规范文档需统一换行，先确认只存在换行差异再写规范字节，不能掩盖内容变化。用户本地批注先备份并列差异，不无声覆盖。

## 5. 冻结后的变更与回滚

任何影响产品行为、生产规则或QA的变化都记录changeId、理由、受影响模块、前后diff和重验范围；升级版本，重新审定相应变化。错字修订可按明确范围缩小审核，但不能偷偷改变批准语义。

暂停优先于旧批准；恢复需要用户明确解除暂停及对应版本／范围。失配50词历史稿保留，不作为默认基准，不继承它的内容pass／模块锁。若要复用其中某项，只能作为待重新审查的材料进入当前流程。

发布回滚恢复上一正式release指针和静态产物，不回滚或清空用户学习事件。失败候选保留记录供诊断；不得为回滚删除日更数据、清浏览器存储或重置FSRS。发布、词库回填、自动任务切换分别记录范围，不互相授权。
