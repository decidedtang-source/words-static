# 数据接口、字段归属与依赖

本文件定义拟实施合同。名称和字段供后续实现，不宣称当前生产器已有这些接口。

## 1. 身份、来源和共用类型

原entryId/cardId保持不变；字面相同但来源／原句不同的入口不自动合并。`lexicalEntryId`表示词或整体表达的词典身份；`contextId`表示一次原句用法。旧三词页面的scope/leverage/absorb键是legacyDisplayKey，仅做适配，不改成全库卡片身份。

ID全部为稳定字符串；version为显式版本；时间用含时区ISO8601；sourceDate未知为null，不能拿抓取日期替代作品日期。Text保存原文及展示转义分离。EvidenceRef含sourceId、sourceVersion、locator（条目／义项／页段）与supportedClaim；只有网址不算完整证据映射。

| 实体 | 必填字段 | 重要可选字段／限制 |
| --- | --- | --- |
| EntrySnapshot | entryId、原词目、原句、原批次、原文件SHA、原句SHA | 原meaning/IPA原样留存，不因此认定已核查 |
| LexicalEntry | lexicalEntryId、lemma、expressionType、language | 单词／固定短语／自由组合／术语／交际块可多标签；不按空格直接判义 |
| SourceRecord | sourceId、版本、标题、出处、accessMode、retrievedAt、coverage、rights、limitations | indexed_excerpt / page / licensed_snapshot / user_material明确区分；正文引用身份另存 |
| Sense | senseId、lexicalEntryId、pos、meaning、sourceRefs、version | sourceSenseId或人工locator；用法标签；中文整理；新增场景不必新增sense |
| SenseInventory | inventoryId、version、lexicalEntryId、sources、senseIds、coverageStatus | 指定来源内的覆盖范围，不等于全语言穷尽 |
| LearningSelection | entryId、version、inventoryRefs、selectedSenseIds、reason、general、senses[] | 每义双语例句／用法／来源；频率证据缺失时不排名 |
| ContextUse | contextId、entryId、sourceRef、quote、quoteSHA、translation、quoteType、meaning、qualifiers、location | senseRefs或组合解释、targetSpans、必要上下文；unresolved不得强填确定义 |
| HistoryRecord | lexicalEntryId、version、summary、claims[]、sourceRefs、limitations | claims有claimId、时间精度；无来源不造内容 |
| BridgeRecord | entryId/contextId、version、location、strategies[]、anchorRefs、targetRefs、semanticText、boundary、evidenceRefs | historyLink、historyClaimRefs可空；现代桥不依赖历史存在 |
| PracticeCard | practiceId、version、activity、goal、roles、evidenceCriteria、questions、responses、boundaries、sourceRefs | 资料事实与编辑教学解释分开；不是公司统一制度 |
| AnalysisRecord | entryId/contextId、version、promptHash、depth、depthReason、coverage[7]、blocks[]、workplaceUse[]、practiceRefs、edges[] | coverage为expanded/integrated/not_needed，后两者附理由；2–5工作句 |
| ReviewRecord | reviewId、reviewer、role、scope、inputHash、artifactHash、checks[]、verdict、issues、time | 文字／来源／完整包／页面分开；不得由字段检查签语义pass |
| CandidateManifest | batchId、planFreezeId、runAuthorizationRef、entryIds、itemStates、dependencies、moduleLocks、metrics | fullPackageApproved与published分别计数；缺口／失败可对账 |

所有实体都有schemaVersion；未知字段和类型错误在边界拒绝，不能靠模板忽略。可选字段缺失必须走明确缺省分支，不把null字符串显示在页面。

### 关键嵌套字段的固定含义

- Sense.meaning：`{definitionEn, glossZh, glossOrigin}`；中文来源为editorial／licensed_translation等明确身份，不能用单一meaning字符串混淆原定义和场景总结。
- LearningSelection.senses[]：`{senseId, title, usageLabels[], explanationZh, examples[], evidenceRefs[]}`；examples每项为`{en, zh, origin, sourceRef|null, usageNote}`，origin区分licensed／short_quote／original。
- ContextUse.qualifiers：`{polarity, modality[], conditions[], agents[], timeScope, excludedInferences[]}`；保存原句可支持的约束，不填未经证实的组织权限。targetSpans每项为`{start, end, text, mappingType, note}`，start含、end不含，按原句Unicode码点计数；实现必须显式处理代理对，不能混用UTF-16下标。
- ContextUse.expressionExplanation：`{kind, text, componentRefs[], wholeExpressionRefs[], boundary, reviewerBasis}`；kind为fixed／technical／compositional，sourceRefs与解释范围必须相符。是否足以解释由独立内容审阅判断，非仅统计引用数量。
- BridgeRecord.historyLink：`{text, relationType, claimRefs[], limitation}`或null；returnTargets指向stable sense／history ID，视图适配为原锚点。缺史源不能以空字符串加“已核查”状态冒充。
- AnalysisRecord.coverage：七个固定键syntax/concept/contrast/languageGame/englishNeighbors/pragmaticAction/workplaceUse，各为`{mode, reason, blockIds[]}`；blocks为`{blockId, dimensions[], text, sourceRefs[]}`，按教学顺序排列。
- AnalysisRecord.edges[]：`{type, targetId, targetVersion, explanation}`；PracticeCard.evidenceCriteria为`{neededEvidence[], decisionCriteria[], limits[]}`；角色含roleName、responsibility、authorityBoundary，未知权限写明未核实。
- AnalysisRecord.workplaceUse[]：`{en, zh, whenToUse, limitation, origin:"original"}`；非原创例句只能归资料／学习模块，不伪标原创。
- ReviewRecord.checks[]：`{qaId, result, observation, evidencePaths[], issueIds[]}`；scope明确，full_package审核必须覆盖本条全部所需内容QA，不能只放一个“通过”标记。
- CandidateManifest.itemStates[]：`{entryId, contextId, revision, state, inputHash, artifactHash, reviewRefs[], blockers[], revisionAttempts}`；revisionAttempts初稿为0、两次修订分别1和2，超过2拒绝继续自动修订。

输出构造时不向使用者展示这些制作字段；其作用是保证正文、关系与证据可追溯。

## 2. 九模块字段归属与兼容映射

| 模块 | 拥有／读取 | V9投影与升级安排 |
| --- | --- | --- |
| M01 | 词头／IPA／pos；读取Entry身份 | 保留word/ipa/pos，来源元数据放外层；view默认不改 |
| M02 | 不拥有原句；读取M07 | 同一quote/translation/meaning渲染；接口可保持无自有字段 |
| M03 | 不拥有释义；读取M05/M07与锚点 | general/meaning来自各自模块；旧跳转不变 |
| M04 | inventory及源sense映射 | 新数据接口v2，保留dictUrl/extra的显式v1兼容层 |
| M05 | selection、例句、note | general/senses/note等逐字段适配；新sense引用按接口增量登记 |
| M06 | 词史claims与summary | history/historyUrl兼容；多来源和claim引用按增量接口登记 |
| M07 | quote、translation、context、meaning、qualifiers | 保留现有显示字段，新ContextUse来源／引用为v2层；不静默改quoteType |
| M08 | semanticText、historyLink及路线 | bridge/bridgeHistory兼容，路由／锚点新增为v2接口 |
| M09 | 七维、自然段、工作表达和Practice引用 | 明确v2；旧五区字段只供历史渲染，不自动拼成七步 |

内容适配器只做字段映射、选择和安全转义，不生成释义。`toLegacyReadingProjection(entry, context, resources)`输出原壳能消费的字段；`toV10AnalysisProjection(analysis)`输出新后部。映射失败返回结构化错误，不填“通用解释”。新数据包可按entry/context分片；M01等无关view不因全库身份升级而重写。

## 3. 依赖与失效传播

| 变动 | 必须重审／检查 | 不应自动重写 |
| --- | --- | --- |
| IPA或音标来源 | M01与发音标签QA | 释义、Bridge、七步 |
| 源sense定义／范围 | 实际引用该sense的M05/M07/M08/M09，M03摘要一致性 | 未引用该义的条目 |
| 精选义／例句 | M05；引用其锚点的Bridge；M03通用摘要 | 无关场景原句与独立历史 |
| 原句／译文／限定 | M07→M02/M03/M08/M09及相关审核 | 原词典库存本身 |
| 历史claim | M06与引用此claim的Bridge历史、相关分析 | 无历史依赖的现代Bridge |
| Practice内容／边界 | 实际引用版本的Analysis本地说明及关系 | 其他Practice和未引用条目 |
| Prompt或生成规则 | 使用该版本产物的内容复核；差异评估后重生成 | 旧已冻结版，不原地覆盖 |
| CSS／壳／共享事件 | 全九模块布局与交互QA | 通过技术改动不触发无意义语义重写 |

制作依赖图是有向无环图。历史是Bridge的条件依赖；M04→M05→M07候选定位并不意味着M07只能采用精选义。词典与场景可共享源证据，但不循环修改对方的正文。

## 4. 指纹、审阅与原子封包

输入哈希包含entry/context身份、原句及必要上下文、所引用sense/证据实际内容和版本、Prompt、生成合同、Practice内容和版本；规范JSON排序后SHA-256，时间戳不进入语义输入。源文件原字节SHA另外保存，不能用规范哈希冒充原字节一致。

稿件哈希覆盖所有面向读者的文字、译文、例句、桥、边界、引用和内容版本；审阅记录／可变状态不纳入稿件自哈希。输入不变但稿件改变，旧审核同样失效。内容／接口／视图／流程锁分别覆盖各自文件；view只改布局也必须重跑布局QA。

写临时稿→结构校验→原子提交条目版本→更新manifest；中断只恢复输入和产物哈希匹配的完整版本。旧accepted版本不可覆盖，候选使用新revision路径；指针更新和内容版本写入有可恢复记录。复跑读取持久化状态，不能汇总时统一写drafted。

## 5. 保全与展示分离

保留原词库15批、1875 ID及原句，候选放独立资料层；新内容的中文修正不改原snapshot。禁止候选脚本写IndexedDB、FSRS或自动导入备份。后续正式学习集成以同entryId挂载额外阅读资源，需要单独兼容验收。

学习正文只呈现必要来源与不确定性。来源失败详情、route枚举、哈希、审核者、费用和状态日志在审阅报告。审阅目录可以显示阻塞；发布正文不能把未决内容包装为已解释。
