# M08 · Bridge：语义联系与折叠历史联系

## 目的与基准

Bridge把前部可靠词义与后部当前语境连接起来，是重点质量管控模块。保留 `word-page/modules/bridge/` 的普通段落、回看通用义项按钮、默认语义联系和折叠历史联系，锚点 `wl-bridge / wl-bridge-history`。不重做成流程面板，不把传统历史区搬进来。

## 输入与输出

输入M07已确认的ContextUse、M05精选引用、M04库存／补充sense、必要专业概念；仅历史分支按需读取M06的历史claim。无历史资料不是现代Bridge生成的硬依赖。

输出BridgeRecord：entryId/contextId、location、strategies[]、anchorRefs、targetSenseRefs、semanticText、boundary、historyLink|null、historyClaimRefs、returnTargets、evidenceRefs、version。旧 `bridge/bridgeHistory`由明确适配输出，不在renderer现场决定路线。

location只说明义在哪里定位；strategies说明怎么解释，可组合：direct、contextualization、evidenced_modern_link、memory_analogy、needs_specialist_concept、no_derivation。复杂程度、字数或depth绝不能决定语义路线。

## 六种具体处理

| 情况 | 正文组织 | 不能做 |
| --- | --- | --- |
| 精选已有当前义 | 指向该义，说明对象／范围在本句如何具体化 | 再抄整段词典定义 |
| 库存有义但没精选 | 在当前用法旁补充该sense，给回看入口，再解释联系 | 强行改精选排序或套第一义 |
| 外部来源补充义／术语 | 先确认证据，补概念，再讲有限联系 | 先编桥再找支持 |
| 原义语境具体化 | 保持原sense，写本次适用对象与边界 | 为每种工作事项发明新词典义 |
| 专业／制度／固定表达 | 先解释整体成立条件；可联系普通义，但明确不能完整推出 | pupil=入瞳、普通vote自动推出制度权限 |
| 证据不足 | 停止肯定性桥，记录缺口，候选包阻塞 | 带警告仍给确定结论并计入合格 |

## 历史联系不是传统历史模块

默认语义桥和折叠历史桥是同一页面的两个层次，不做互斥二选一。历史桥回答“已核查的历史用法与当前义能怎样联系”，M06回答“这个词的历史用法是什么”。M08引用M06不等于照抄一遍。

有可核查历史关系时，在折叠区写关系、证据与不能推出之处，并保留回看M06链接。只有词根资料而没有当前义演变证据时，只能有限说明，不说“因此发展成此义”。完全无依据时保留简短缺省说明；详细检索过程不进正文。已有可靠Bridge历史不能无理由丢弃。

## 文案与审核

一条桥应使读者知道：当前用哪一个义／表达；从哪个已知锚点进入；共享什么；什么仍需要专业概念或证据。简单直接适用可一两句，不能为形式凑隐喻。记忆类比须自然标“可以这样帮助记忆”，不作为历史或定义证据。

审核至少做四个反问：换成另一个词义还能成立吗；有没有遗漏原句限定；是否暗示尚未发生的批准／责任／结果；历史关系是否超出了史源。失败回到对应场景／义项／史源修订，不只润色桥文。

## 版本与QA

本模块新路由及引用属于接口增量；view只加必要的补充锚点，不改基准视觉。上游语义变化使桥审阅失效；历史变化只影响有历史引用的分支。每个分支分别保存依赖哈希，但发布时同一Bridge版本必须一致。

QA `Q-B01`定位与策略正交，覆盖六种情况；`Q-B02`每个联系／边界有依据，无强推导；`Q-B03`双历史区职责与折叠／返回；`Q-B04`原句限定及专业规则；`Q-B05`缺史源可正常现代解释、缺词义证据则阻塞；`Q-B06`depth改动不改变路由、历史引用变化选择性失效。Bridge未通过内容QA，M09不能视作可验收，即使英文表达顺畅。
