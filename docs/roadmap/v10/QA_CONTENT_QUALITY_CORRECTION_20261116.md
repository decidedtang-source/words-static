# QA职责修正：检查结构与流程

依据用户最新明确说明：**QA是为了应对结构和流程问题。** 本文件取代上一版将内容审阅作为QA重点的建议；当前只更新方案，尚未修改运行代码和旧冻结记录。

## QA检查什么

- 页面结构：约定模块齐全、顺序正确，普通历史与Bridge内历史分开；场景例句在Bridge之前。
- 固定字段与接口：必需字段、类型、引用和词条对应正确；无串词、缺块、重复或截断。
- 页面交互：折叠、导航、返回、发音按钮正常；多屏布局可读，无空壳或溢出。
- 生产流程：该抓的资料是否实际抓取、解析和保存；各步骤是否执行；结果是否完整传给下一步。
- 故障恢复与版本：失败步骤可定位重试，不丢已有成果；版本匹配，不意外覆盖原稿或正式数据。
- 发布流程：实际部署或覆盖时，核对目标、版本和操作范围。

这些能确定检查的规则优先写成脚本。一次发现问题后修复对应字段、组件或步骤，不因为局部问题重写整个词条。

## QA不负责什么

不建立逐词反复语义打分、层层审批或为假设风险削减正文的机制。不因写法存在其他可能，就把完整解释改成空泛短句或补满免责声明。不把字数少、表述保守、限制语多当作合格标准。

内容完整、准确、自然、有解释力属于资料获取与内容生产本身的要求。生产时遵循选定来源和用户的方法；发现明确错误直接局部修正，用户反馈用于改善内容。这不另设一套循环语义QA，也不放任已知错误。

例如：Etymonline没抓取，是流程未完成，修抓取步骤；抓取结果没有进入历史模块，是数据或结构问题，修传递与展示。capacity场景义不合适、Bridge没讲清、分析太空，是内容生产需要改进，不通过增加QA轮次解决。

## 当前范围

保留现有布局；普通词史采用固定资料获取流程。完整词典本轮不动，保留后续成熟词典接入接口。原50词保留供修改，不再把旧“内容审核通过”作为内容质量已达标的证明。

后续实现应删减或拆出与上述职责不符的繁重内容审核门，保留必要的结构和流程检查；不新增一套更复杂的QA制度。本次文件更新不声称这些代码变更已经完成。
