# QA V1.1：基础内容量完整性

用户在结构与流程QA之外新增要求：预设单词/词组的解释量，特别是后部七步分析，检查是否达到基本要求。此项补充此前“不以篇幅评内容”的表述：现在检查最低内容量，但不做语义评分，不把更多字直接等同更高质量。

## 初始要求

| 生产档位 | 七步正文预计量 | 最低通过量 |
| --- | ---: | ---: |
| 简明 concise | 300–500 | 250 |
| 标准 standard | 600–900 | 500 |
| 深入 deep | 1000–1600 | 800 |

这些是本次采用的可调整初值，不是外部标准，也不将旧800/1800/3200 token容量估算直接换算成字数。档位按词条解释需要在生产前确定；不按成稿短就自动改成简明档。已有50词沿用已记录的depth，不为了通过改档。

计数单位：一个汉字计1；一个英文词或数字词计1。空格、标点不计。重点统计七步正文自然段，标题、元数据、来源词典、普通词史、例句/译文以及单独的工作例句引导段不计；完全重复段落只计一次。七步可以合并显示，不要求七段等长。双语工作表达另检查至少2条，不设超长惩罚或自动截断。

另报告`explanationUnits`：场景义＋Bridge＋分析的去重文字量，仅供整体参考。不同词的义项与来源长度差异大，不让前面词典很长掩盖后部没展开。

## 结果与补写

- 达到最低正文量且有2条双语表达：`pass`。
- 未达到：`needs_expansion`，报告实际量、最低量、差额及表达条数。内容任务待补，已有正文保留，仍可预览。
- 没有生产档位：`unconfigured`；先登记预期要求，不由QA猜测或按现有长度选档。
- 超出预计区间：仍可通过，不减分、不删字、不截断。

补写应补缺失解释、辨析、搭配或实际表达。QA本身不自动调用模型凑字、不强制添加免责声明、不反复改写。长度通过不证明内容准确或好用；内容问题仍在正常内容编辑中处理。

个别词可在run的`content-budget.json`用`entries[entryId]`登记`profile`，必要时用`minimum/target/reason`给出不同要求；例：`{"entries":{"V20261012-012":{"profile":"standard"}}}`。自定义数值须有效且记录理由，不能用零下限关闭检查；超过下限即可，不需要为了落进区间删除内容。

## 与结构、流程的关系

结构合格＋页面通过 → 可以预览。
结构合格＋资料流程完成＋基础内容量通过＋页面通过 → 本次生产流程完成。
