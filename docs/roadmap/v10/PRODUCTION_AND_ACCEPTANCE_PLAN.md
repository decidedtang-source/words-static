# V10 生产与验收实施计划

> 后续获准实施的代理按任务逐项执行；采用可用的 executing-plans 或 subagent-driven-development 工作流。本文记录计划，所有未完成框均不是完成声明。

**Goal:** 在 V9 兼容基准上，为既有 1,875 个入口建立可复用的义项定位、Bridge、七步分析与共享实践生产链。

**Architecture:** 原始数据只读；证据、义项、场景、教学分析与发布分层。先生成可独立验收的内容包，再接回九模块，构建不联网改写内容。

**Tech Stack:** 延续现有 Node、JSON、HTML/CSS/JS、静态构建和既有浏览器测试；不预设新增后端或付费服务。

**Spec:** [系统与页面](SYSTEM_AND_PAGE_DESIGN.md)、[内容合同](CONTENT_AND_BRIDGE_SPEC.md)、[V9 冻结](../../baselines/WORD_SYSTEM_V9_20261116.md)。

## 全局边界

保留全部原 entry/card ID、源例句、15批资料、FSRS与IndexedDB/备份契约。V6–V9与历史候选不覆盖。词库回填、内容发布、网页发布和定时任务切换各自有授权与证据。本轮仅规划写入，未启动生产。

## 现有基准 → 下一步

现有词库更新按 `content/YYYY-MM-DD.json` 与 `scripts/update-vocabulary.mjs` 校验导出；三词页面先由人／助手核对来源，再离线构建。下一步只在它们前面增加可验收的内容生产及适配层，不假装现有模块化已等于全量生成器。

未来流水线：输入快照 → 类型与深度分配 → 原句用法判断 → 来源／义项补充 → 精选与场景映射 → Bridge 路由 → 七步与共享实践 → 独立语义复核 → 修订与版本封包 → 静态适配／回归 → 经授权发布及回读。

## Review Focus

1. 当前义不在常用列表：能补充，不强配高频义。
2. 专业短语／组合表达：整体身份正确，不把组合义伪装成单词义。
3. 否定、条件及来源缺失：原句限定保留，unknown 不自动 pass。
4. 上游或共享实践改变：受影响产物失效或重审，不全库无差别重写。
5. 旧学习数据及移动端：内容升级不能重置记录、破坏阅读或强制联网推理。

## Task 0：基准盘点与分类清单

输入：V9 原词库与模块锁。输出：每个稳定 ID 的原句指纹、类型、深度候选、资料缺口、待处理状态。

- [ ] 先写测试：ID 集合相等；原句保留；总数为实际读取值；类型与深度不由词条标签硬映射。
- [ ] 只读遍历原数据，核对单词、含空格短语、连字符项目；已有统计 1,875／1,597／22／256 作为复核预期，不据此猜每条类型。
- [ ] 保存规划与实际数差异，测试通过后提交清单；不得改原词库。

建议新文件范围：`content/enrichment/v10/manifest.json`、`scripts/analysis-workflow/`、`tests/analysis-workflow.test.mjs`。这些是拟新增路径，本轮未创建或实现。

## Task 1：证据、义项与场景合同

输入：原词条、按需原材料和允许使用的词典／专业资料。输出：带来源范围的 sense inventory、learning selection、context mapping。

- [ ] 先写失败用例：常用义缺失但库存有义；库存缺失但有外部依据；组合术语；只是语境具体化；仍未知。
- [ ] 为 source、sense、context 建立稳定身份与版本。保存使用许可、引用类型、检索失败和核查范围。
- [ ] 对旧模块写显式适配器；不得把远程返回结构直接散落在页面。
- [ ] 确认 missing／unresolved 不会被生产路径自动改成 verified。

资料接入不得绕过访问限制；付费授权、API、自动抓取器均需明确来源能力，不能写成已存在。正文以原创整理与允许的短引为主，许可原文单独管理。

## Task 2：Bridge 路由与代表词校准

输入：Task 1 映射和必要概念。输出：Bridge 文本、锚点、关系类型、边界及审核记录。

- [ ] 测试上述 Review Focus 1–3，并区分“查找位置”和“联系方法”。
- [ ] 选 24 个校准入口，覆盖单词、短语动词、组合术语、交际块、低频义与跨实践用法；scope、leverage、absorb 可保留为页面对照，ownership、reservation、working definition 可作方法对照。
- [ ] `entrance pupil` 等外加例只用作测试夹具，不默默增加或替换 1,875 库存。
- [ ] 先核实专业事实后写 Bridge；审阅确认没有伪词源、伪频率或把类比当定义。

## Task 3：共享实践资料与七步生产

输入：原始 Prompt、已核实 ContextUse、Bridge、实践卡。输出：有本地解释且引用共享资料的七步 Analysis。

- [ ] 写测试：一个词可关联多个实践；无合适实践可不强挂；边必须有关系说明；共享版本变化会触发相关条目重审。
- [ ] 从真实词条归纳第一批实践，数量以有用为准，20–30 只是初始预算。
- [ ] 生成三档内容；不把短版降成翻译，不把长版写成重复模板。
- [ ] 每条保留七维覆盖／未展开理由，而不是强迫显示七个标题。
- [ ] 每词须能独立读懂当前实践中的位置；不能仅给共享页链接。

## Task 4：独立审阅、修订与断点恢复

状态机：`queued → evidence_ready → drafted → reviewed → accepted`；可进入 `needs_revision`、`blocked_evidence`、`rejected`。`accepted` 不等于 `published`。

- [ ] 写失败用例：同输入重复运行无重复产物；修改原句／义项／prompt／实践版本后不能复用旧审核；中断不把半成品标完成。
- [ ] 以 entryId + contextId + input fingerprint + prompt version 建立幂等任务。保留每轮稿、审阅结论、差异和原因，不覆盖最终批准版。
- [ ] 每条都有内容语义复核。高歧义、专业事实、责任／批准类再做加强复核；自动 schema 检查不替代语义审查。
- [ ] 对反复失败项限制重试次数并报告 blocker，避免无限自审耗费预算；其他条目可继续，失败项不藏在总数中。

## Task 5：全量生产

- [ ] 24条校准后完成100条跨类型验证批，再分批覆盖剩余项；这两个批次计入最终总数，不额外重复计费。
- [ ] 调度批可为50–125条，实际单次生成子批先用5–10条并共享精简上下文；不要把整个仓库和全部词库反复送入每条任务。
- [ ] 不同任务只写独立产物；共享义项／实践由单一合并阶段登记，禁止并发互相覆盖。
- [ ] 每批记录 drafted/reviewed/accepted/blocked 数量及成本，汇总必须能与1,875个稳定ID逐一对账。
- [ ] 验收后才推进下一批；深度配比以质量校准，不为凑560/940/375而强行降档。

## Task 6：九模块与原学习应用集成

- [ ] 先写旧词条／旧事件／旧备份回归测试，确保稳定ID和排期不变。
- [ ] 提升 analysis 及必要上游模块的 interface/content/process 版本；沿用 registry/lock，不大改无关模块。
- [ ] 新增不在精选列表的场景义时有清晰补充卡；Bridge 正文无需暴露编辑日志；七步保留连续阅读和锚点。
- [ ] 全量数据按词／批分片，按需加载；不要把约334万输出token的全部分析塞进初次HTML或一次响应。
- [ ] 复核搜索、原文／深析复制、发音播放／结束／错误、减少动态效果和窄屏溢出；真实Safari/设备未测必须单列。

## Task 7：发布、回读和后续增量

- [ ] 先保存候选内容版本、module lock、审核清单、旧版回滚入口。
- [ ] 收到针对发布的授权后才更新线上入口；不凭本规划直接合并运行改动或发布新数据。
- [ ] 按获准范围构建并验证实际远端内容；源提交、构建成功、部署成功、用户实测四种证据分开。
- [ ] 下一阶段再规划增量词条、纠错闭环、学习反馈、自动同步；不在本期顺带修改Podcast或定时任务。

## 预算与完成标准

初始正文预算：560×800 + 940×1,800 + 375×3,200 = **3,340,000 输出tokens**；不含研究、输入、推理、审核与重写，也不是订阅百分比。记录实际可取得的用量；取不到的字段记unknown，禁止估算冒充实测。

最终交付1,875项处理索引、可追溯义项、场景映射、Bridge、七步、共享实践、审核记录、未决项、候选站点和兼容验证。未通过者显式列出；全库验收不能靠用通用话术填满所有条目。

学习者检查至少包含：能解释语义联系及边界；能区分相邻表达；能判断当前话语的实际动作；能理解或回答一个未见过的新场景。
