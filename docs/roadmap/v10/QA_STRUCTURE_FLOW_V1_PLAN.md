# QA结构与流程 V1 实施方案

> 执行方式：使用 executing-plans 在当前隔离工作区顺序实施，完成后做一次代码复查。用户已明确要求规划后更新并冻结，不再另设方案批准门。

**Goal:** QA只检查结构和流程，不以逐词语义审阅阻断生成或预览。
**Architecture:** 新QA入口读取现有内容包，检查固定合同、资料步骤与实际页面；不改写内容。旧R2命令和冻结证据作为历史保留，新入口不调用其独立内容审核门。
**Tech Stack:** 现有Node、JSON、Playwright，无新增服务或模型调用。
**Spec:** [用户最新职责修正](QA_CONTENT_QUALITY_CORRECTION_20261116.md)。

## 检查清单

| 编号 | 检查 | 失败处理 |
| --- | --- | --- |
| S01 | 词条ID唯一、原句与快照对应、包未串词 | 修本条映射 |
| S02 | 九模块所需数据存在，显示字段可读取 | 修缺字段/模块，不重写正文 |
| S03 | sense/source/Practice引用及数组结构有效 | 修引用或数据传递 |
| P01 | 已登记输入/稿件与实际文件一致 | 重新登记对应版本，不继承旧检查 |
| P02 | 普通词史获取、解析、保存、传入页面有记录 | 仅该步骤待补，不停其他内容生产 |
| P03 | 必需任务未完成不能以占位文字算完成 | 报完成数与待补清单；允许带状态预览 |
| L01 | 模块存在、顺序正确、两处历史独立 | 修模板 |
| L02 | 切词、折叠、导航、发音控件可用 | 修对应交互 |
| L03 | 窄屏/手机/平板/桌面无横向溢出、无JS空壳 | 修布局/渲染 |
| V01 | 本次QA规则与脚本冻结文件哈希一致 | 明确版本改变，另出新冻结版本 |

不检查“措辞够不够谨慎”，不要求逐词独立审阅证书，不以段数/篇幅/免责声明评定内容。已知错义或错译在内容编辑中直接修正，不另设循环QA。

## 结果定义

- `structurePass`：固定数据合同完整，可用于渲染；不代表教学质量已达标。
- `flowComplete`：本轮必需资料步骤已完成。失败、未执行、缺记录分别列出；确认无词条作为明确例外记录，不虚构正文。
- `previewReady`：结构及实际页面检查通过，可交用户试读。资料未齐可预览，但必须并附待补报告。
- `productionComplete`：结构、流程及本次页面检查完成。只表示流程完成，不表示内容评分、用户接受或已发布。
- 发布作为独立动作，本次不部署、不改变正式数据。

词史流程回执：`entryId/module/sourceId/status/url/fetchedAt/artifactPath/artifactSHA/extractedText`，成功时必须能核对实际保存资料及页面使用的同一来源；状态区分`not_attempted/fetch_failed/parse_failed/ready/no_entry`。`no_entry`必须有保存的查找结果与理由。QA不执行网络抓取或自行编写缺失词史；抓取适配器属于资料生产工作。

完整词典本轮退出新增抓取任务，仅检查已有接口数据可读；不新增词典内容，不改变其布局或来源。

## 文件与任务

### T1 结构/流程检查器
新增 `scripts/qa/structure-flow.mjs`、`config/qa/structure-flow-v1.json`、`tests/qa-structure-flow.test.mjs`。
接口：`checkBundle(bundle, acquisition, evidenceRoot)` 返回固定检查结果；`checkRun(dir)` 只读原包、逐词汇总，不要求reviewed状态。资料回执读run内`acquisition.json`的records数组。
- [ ] 先测试缺模块/串词/未执行抓取/失败占位/正文不改/辅助qualifiers缺省不阻断/无语义审核仍可通过结构检查。
- [ ] 实现最小检查器，验证通过。

### T2 页面检查及新默认入口
新增 `scripts/qa/cli.mjs`、`scripts/qa/page.mjs`；修改 `package.json` 加`qa:check/qa:page/qa:preview/qa:verify`，`config/qa/current.json`指向新版本。
接口：`checkPage(html, expectedIds)`检查实际页面；预览调用现有渲染器，绕开旧reviewedBundles门，不更改原内容包或原冻结页面。输出写到新指定目录，禁止覆盖已有目录。无--output时只检查并输出JSON。
- [ ] 测试默认版本、新入口不要求语义审核、旧冻结目录不得覆盖、错误结构明确返回、待补资料不阻断预览。
- [ ] 复用原模板；实际检查50词页面结构，记录真实缺失流程回执，不生成新内容。

### T3 冻结与交付
新增 `scripts/qa/freeze.mjs`、`config/qa/freezes/structure-flow-v1.json`，记录本次用户授权、版本、固定文件哈希和检查结果路径；`verifyFreeze()`逐文件核对，变更即报告失效。
- [ ] 测试冻结后修改脚本被发现，原冻结记录不被重写。
- [ ] 完成一次代码复查，运行相关测试；冻结方案、规则、实现、入口与测试。
- [ ] 本地审阅目录和GitHub产品分支/上下文仓同步新QA状态，正式网站不发布。

## 实施约束与重点

旧R2记录不改，旧数据的“reviewed”不再是新QA的必要输入。新QA不设置内容修订次数上限；步骤错误局部修复。抓取回执缺失不能根据现有摘要倒填为抓取成功。浏览器检查失败只阻止该候选被称为页面通过，不阻止写作和保存。原例句、完整词典、1875词库、Podcast保持不变。

当前清单记录计划；实际完成状态另存执行记录，避免事后改写已冻结方案。
