# Owner 产品总纲｜V3 默认 B，按需切换 C1；保留原五区

**最新决策 / 2026-11-03**。状态：**OWNER_DIRECTION_ACCEPTED / CODEX_TO_DECIDE_IMPLEMENTATION / NOT_IMPLEMENTED / NOT_DEPLOYED**。

这是给 Codex 的**产品边界与验收目标**，不是指定技术架构或逐项任务清单。以前 A/B/C 三选一的网页实验是探索材料；本决策优先于“每个词都需要在 A/B/C 中选择一个胜者”以及“四区/三区替代五区”的旧计划。

## 一、总体界面（稳定的结果）

```text
V3 现有词头 / 中文短义 / 当前有据词典义项 / 本句先记 / 其他义项折叠
                         ↓
独立、不编号的 Semantic Bridge（词义联系）
            默认 B ｜ 可切换 C1（深入词义）
                         ↓
原 01–05 五区全流程分析（完整保留，不替换、不改编号）
                         ↓
原学习例句 / 复制原文 / 复制【深析】/ 原评分与记录
```

- **B 默认**：像成熟词汇学习产品一样讲词。优先选真实而熟悉的**现代常见基本义**，用恰当的日常/工作场景说明如何联系到当前语境义项，再回到原句。讲清楚中间的意义转换，而非只罗列互不相关的释义。若语义联系不自然，就明确分开记；习语先讲有据的整体义；词组和整句是一条学习对象。
- **C1 可选切换**：给愿意进一步研究的学习者提供**更有来源证据和词义细节**的另一种解释，包括必要的义项区别、词形/搭配、不同可靠词典的用法核对，以及有证据且真正有价值时的历史词源。C1 **不等于每个词都生成长篇词源学**，不应无证据杜撰历史演化。来源未覆盖时清楚告知，不假装有完整考据。
- **A 不再是用户可见模式**。Codex 如有必要可把短小词典直连型解释作为**内部 QA/对照基线**，无需为 A 设计第三个用户切换状态。
- **切换只影响词义桥**：用户在 B 和 C1 间切换，不触发评分、FSRS、复习状态变化，不更改当前选择义项，不更换或重排五区。产品应支持返回默认 B；无可审的 C1 资料时，不呈现伪造内容。
- **原五区 01–05 完整保留**：Memory/Semantic Connection、Syntax/Concept、Contrast/English Neighbors、Language Game/Pragmatic Action、Workplace Use。Bridge 是词典与五区之间的过渡，不能替代它们，也不能逐词重复完整五区。
- **V3 词典区保持设计**：目前词典义项及本句在上，其他已核义项的展开/收起、来源/版权限制和学习页面分层继续使用现有产品方向。

## 二、留给 Codex 独立决定

以下**不在此定死**，由 Codex 研究代码、提出比较并选择最小可靠方案：

- B/C1 是怎样的组件状态、命名、层级、交互、加载和无 C1 来源时的降级体验；
- 如何组织合法词典证据、现代义锚点、场景桥、历史补充，如何避免重复；
- 数据模型如何扩展、版本化/来源/审核状态如何保存、对旧 v1/v2 分析数据如何兼容；
- 是否需要分角色 Writer/Reviewer，以及最少哪些自动测试能有效阻断虚假考据、断裂的意义联系和 UI/FSRS 回归；
- A 是否值得保留为内部简洁性 benchmark；何时只生成 B，何时为 C1 进行额外资料研究。

但其技术选择必须能解释权衡，不得以“Codex 自主决定”为由越过下面的验收边界。

## 三、Codex 先复现、评估、再实施的工作流程（建议，高层而非刚性步骤）

**阶段 1 · 审查基线**：阅读 PR #5、现有 V3 实际代码、[双模块 Workflow](TWO-PART-LEXICAL-WORKFLOW.md)、[15 版本初评](TWO-PART-WORKFLOW-REVIEW.md)、[词义讲解路径](WORD-SENSE-PATH.md)及本文件；区分“已经实现”“离线演示”“仅是计划”。梳理真正的证据与版权/隐私边界。

**阶段 2 · B/C1 复现与比较**：在同一 V3 页选择多种目标（如 shift、working definition、outcome framing、take into account、条件式排程句），**保留完全相同的词典区与完整 01–05 五区**，仅比较 B 默认和 C1 按需深入。让两种解释真正不同，不只是换标题。具体原型形式由 Codex 决定，须提供桌面与手机可读预览。

**阶段 3 · 审阅和评分**：先检查来源合法性、词性义项准确、实际语境界限，再评价记忆性、语义桥合理程度、额外解释的价值、与五区的重复程度、可读性。Codex 自行选择适当的评分量表和测试方案，但要说明评分依据与不确定性；**资料/语义/版权/隐私重大错误为硬失败，不能由平均分掩盖**。Writer 自评不代表独立审阅；历史 review receipt 不能自动批准新 B/C1 内容。

**阶段 4 · 实施候选**：在独立 feature 分支上按研究结论最小增量实现。可修改必要的源文件、测试、受审词条和文档，但不允许覆盖真实 cardId、FSRS/IndexedDB 学习事件或已有备份，也不更改 Notion 选词、现存发布者和自动化。正式网页只经现有 GitHub Pages 产品发布链。

**阶段 5 · 验收与发布门**：提交 PR、真实浏览器结果、独立内容审核证据、负例、兼容性与风险/回滚方案供 Owner 试用。**允许 Codex 开始分支实现，但没有单独授权合入 main/触发 Pages 正式发布**；若发现需要改动生产流程/私有资料/外部服务，先报告再请求权限。

## 四、最小验收标准

1. 学习者打开词条默认看到 B，不需要先点切换才能理解词义联系。
2. 点击 C1 后看到有实质新增来源/概念层次的深入解释，并能切回 B。可用性和展开状态不会改变原学习进度。
3. V3 原词典与**原五区**无内容丢失、无误重排；Bridge 独立于五区且不编号。
4. 多义词允许自然助记联系，但明确区分**现代常用义、教学类比、真实历史词源**；习语不能强拆，组成词不分别复制完整分析。
5. 两种模式都忠于原句，不制造客户批准、组织 SOP、不可核工程事实、未证词源或虚假的商业词典出处。
6. Codex 出具真实对照样例、审阅/评分依据、测试结果、尚未解决的问题和明确的下一步发布判断；不把独立预览当正式上线。

## 五、最终决策边界

**Owner 已选的是用户体验**：B 默认、C1 按需切换、A 不显示、前半 V3 原样、后半原五区完整。**Codex 负责决定实现方法和质量保证方式**。不要求每个词都硬做 A/B/C 三稿，也不要求强迫所有单词讲统一“原始词根”。此次产品总纲不意味着真实 UI 或内容已更新到 GitHub Pages。
