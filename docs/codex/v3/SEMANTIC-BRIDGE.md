### 整体分析单位

一个用户目标 = 一次完整分析。对 working definition，整体词组是学习对象。working 的形容词义、definition 的名词义只是桥接的证据，不能各自生成独立五区，最后才拼成词组。其他组合词、习语、技术术语、句子同理；固定义优先整词，不强行逐词推导。

## 2. Semantic Bridge 应当回答的四个内部问题

这些问题用于 Writer 推导，**不是四个新的独立 UI 栏目**：

1. **选义**：从可靠来源的哪些 lemma/POS/sense 出发？为什么这句不是同词的其他义项？
2. **义项内部连接**：所选英语定义中的哪些意义成分重要？例如 adopted、temporary basis、for further work 的关系是什么？
3. **组合到整个目标**：在词组中修饰词、中心词或习语整体义如何配合，得到什么准确的整体意义？
4. **放回原句并交接到原五区**：原句如何使用这一意义？哪些是句法事实、哪些只是说话者提议、哪些可能是后续工作？用简短衔接句引入原五区。

桥接文本建议**一小段正文＋可选的 2–3 个语义节点＋一句结论**。为保持阅读效率，它不重复词典所有义项，不抢走五区的 Contrast、Language Game、English Neighbors、Pragmatic Action、Workplace Use 的具体解释。桥是过渡，不是第二篇完整深析。

如果不同义项没有自然可靠联系，直接声明“这里选用第 X 义；其他义项不能凭字面推导”，不虚构共同历史词源。不把 mnemonic analogy 当 etymology。

## 3. 贯穿示例：working definition

**真实分析对象**：working definition（一个词组）。

**学习例句**（不是客户原话）：*Let us agree on a working definition of a critical defect.*

### V3 前半区（原样保留）

- 组合短义：工作定义；暂定采用的定义。
- 当前义项：working（adj.）— *adopted as a temporary basis for further work*；definition（n.）— 定义/概念界定。
- 本句先记：先建议约定一个用于当前判断的定义；这是一项提议而非报告已达成一致。
- 更多词典义项：working 4义、definition 2义，维持现有可展开详情。

### 新增、独立且精简的 Semantic Bridge（作为衔接）

本句 working 不是“正在工作”，选择的是“暂时采用作为后续工作依据”的形容词义。这个义项中：

- *adopted* 表示被选来采用；
- *temporary basis* 表示现阶段的依据，并不声称已最终定稿；
- *for further work* 表示这个依据供后续讨论、判断继续展开。

因此它不只是“临时”，而是“**现阶段当作工作依据来使用**”。当 working 修饰 definition（概念的界定）时，说明这个定义的**当前用途和地位**，所以 **working definition = 当前供讨论、分析和分类判断使用的定义**。

放回 *Let us agree on…*，说话者**正在建议**大家形成这样的定义，并不意味着已经获得客户批准或实际上已达成共识。接下来可以沿着这一整体意义进入原五区。

注意：英语词典定义中的 adopted 描述这种形容词义的通常功能，**不能把它当成当前提议在现实中已经被接受的证据**。

### V3 原来的五区继续保留（不要移除）

**01 先记住，再联系**

working definition 可记为“当前先拿来用的定义”。其他 working 义项还有 practical、functioning、operative；这些不同义项不能全部等同于 temporary。这里再次强化的是“**当前可据以工作**”，而不是重复语义桥全部推导。

**02 句法与概念**

working 作形容词修饰 definition；*of a critical defect* 指明要界定的对象；*Let us agree on…* 是共同约定的提议，不是报告已经同意，也不产生正式批准。

**03 辨析与英文邻居**

tentative definition 更强调尚未定案，provisional 更偏暂行，final 更强调定稿，working 更突出当前工作依据；它们并非绝对互斥。criteria、defect classification、working hypothesis、revision 与怎样使用及修订定义的讨论自然关联。

**04 这句话在做什么**

在假设的质量讨论中，说话者希望先建立共同的判断口径，后续可能进一步核对边界案例、证据以及何时修订。这些属于语境中可能的实践，不是词组的普遍定义或已发生的正式批准。

**05 工作中可以这样说**

*For now, use this working definition when classifying defects.*

目前先按这个工作定义分类缺陷。（本项目自编教学句。）

### 为什么这五区不能被 Bridge 取代

桥只解决“**从词典义怎么来到本句的这个意思**”。五区还各自承担其他学习任务：记忆巩固、句法和概念判断、相近表达辨析、语言活动及说话动作、自然英语使用。它们必须在桥后继续展开，形成一条完整学习路径，而不是为了减少标题而被丢掉。

## 4. 对不同学习目标的适应

- 单词、多义词：桥解释为什么选这个词义，以及它和当前用法的可靠语义联系；后五区仍处理完整情境。
- 组合词组：整体为单位，组成词仅作证据；桥解释语义组合；五区分析整个词组。
- 固定表达/习语：桥应承认整体固定意义不可从字面轻易推导，不强行讲“take＋into＋account”的假故事。
- 派生词/词形：桥可从 lemma、形态、词性变化自然进入当前用法；不要所有 -ing 都视为同一词性。
- 技术术语：桥是现实问题、中文技术概念和英语术语的连接；工程结论仍须来源证据；五区继续讨论工程语境。
- 整句输入：整句是分析单位，桥处理关键结构和组合意义；不要为句子里每个词各生成桥及五区。
- 没有真实语境：仍可以有可靠词典和记忆内容，但不能为了五区结构伪造客户会议或具体审批。对不适用项给出明确 N/A 或已标注教学场景。

## 5. Writer → Reviewer → Builder 的工作约定

**Writer（每张新词卡）**：
- 先核定目标身份、source/POS/sense、是否是词典收录的整体短语和例句来源。
- 输出前半 V3 原有内容，再写**独立的 semanticBridge 候选**，最后写 **01–05 displayGroups**；十个 stageEvidence 仍保持，五区的每一步覆盖原方法，不与桥互相取代。
- 一篇 bridge 就服务于一个整体目标，建议按“选义→义内关系→组合→回句”写，必要部分短而具体。
- 如果桥与 01 太重复，精简 01 的重复句而**不删除 01 本身**，保持所有其他区各有独立贡献。
- 使用原有准确出处/许可，标注生成学习例句；仅根据 real sentence 推断说话者的动作，不编造发生过的责任转移或客户批准。

**Reviewer（单独上下文）**：
- 先确认旧 V3 的五区 **01–05 仍存在**且顺序正确，再确认 bridge 独立位于词典/本句提示之后、五区之前。
- 核对 bridge 语义链与所选 OEWN senses 一致；无虚构词源；对多个词组不作逐词整套五区。
- 逐项检查原 Dictionary、Memory、Semantic Connection、Syntax、Concept、Contrast、Language Game、English Neighbors、Pragmatic Action、Workplace Use 的实际内容；不能只查 stageEvidence 非空。
- 检查新增桥与五区的内容衔接及不过度重复；重点查 adopted 描述的语义状态不能被解释为原句提议已经正式发生。
- 只对**确切候选内容 SHA、相应源快照和审核规则**签名。加入/修改桥导致原批准失效，旧的 v2 receipt 不能自动替代新审查。

**Builder / UI（实施另需授权）**：
- 不应通过替换 analysis.displayGroups 来插入桥。原五区的 id、标题、内容、顺序独立保留。
- 若要让静态网站真实显示新增桥，设计单独**有证据、有审核、可版本化**的 bridge 内容字段/sidecar（位置：Dictionary 和 five-analysis 之间），同步扩展 schema、validator、review receipt 与源内容 hash；不能只在前端凭模型/JS从释义现场生成未审核桥。
- 现有 v2 schema 允许4–5 groups 是旧兼容合同：不要直接把历史 v1/v2 设为 FAIL。**对按本新标准生成、有真实语境的 V3 后续词条，业务 QA 要求五区完整**；如某区证据不足，明确说明不适用/待审核，不能凭空凑内容。
- 严守 cardId、FSRS、IndexedDB、导入/导出、原文/深析双复制、音频权限、额外词典折叠、手机评分栏与 GitHub Pages main 发布门。

## 6. 独立 UAT 验收（内容与交互）

- **页面顺序**：V3 原词典/本句 → Bridge（单独一块、默认可见、无 01 编号）→ 01/02/03/04/05 五区 → 学习例句与复制；不能出现“新版三部分／原版五组”这种替代逻辑。
- **两种对照**：预览中的“无桥 V3”与“有桥 V3”只差一段桥，原五区和前半必须逐项相同。
- **语义质量**：每个桥都能回答“为什么选择这个义项、为什么组合成这个目标意义、为什么这句话这样说”，而原五区各有独立职责。
- **不重复且有连接**：桥到 01，再到 02–05，读起来像完整分析过程；允许有必要的复述巩固，禁止反复粘贴同一段。
- **多类型负例**：working machine≠暂定；outcome framing 的 framing 名词性核心不能被一概改成进行时；take into account 不按 account=账户逐字解释；工程 E 不得伪造图纸批准。
- **学习安全**：隐藏答案时桥不能泄题；显示后桥与五区直接可读；查看/复制/折叠不触发评分；320–1440px 无溢出。
- **发布诚实**：静态 HTML 独立样机、GitHub 文件或测试成功≠已上线。PR #5 的当前五项内容原审查仅涵盖旧 hash；桥加到正式候选后须重新独立审核和 Owner 验收，才考虑 G2 发布。

**最终一句话验收：词典说“是什么”，Bridge 说“为什么这样成为当前的整体意思”，原五区再说“怎么记、句法怎样、与什么不同、说话者在做什么、实际怎么用”。**
