# Semantic Bridge｜让词典义项、组合意义与语境解释连续起来

状态：**CONTENT-AUTHORING STANDARD / PROPOSED FOR PR #5 REVIEW**。本文件是内容方法与验收模板，不代表已增加运行时字段或 UI 控件。

## 1. 本轮要修正的不是篇幅，而是解释的断裂

当前 working definition 示例的各个部分大体正确，但阅读时会经历一次跳跃：

- 词典：working 有四个形容词义项；
- 语境选择：这里采用 *adopted as a temporary basis for further work*；
- 组合短义：工作定义；暂定采用的定义；
- 后文：句法、辨析、语言游戏、工作表达。

缺失的是**从上一个结论到下一个结论的理由**。学习者看到了多个正确答案，却看不见它们如何相互推出。

新标准：每一阶段不仅回答“是什么”，还要回答“为什么从上一阶段可以走到这里”。不能用更多同义词、更多标题或单独列搭配来冒充桥接。

## 2. Semantic Bridge 的定义与边界

**Semantic Bridge（语义桥接）**：把可核实的词典义项，经过语境选义、词形/句法关系或词组构成，连接到当前表达的具体含义；再说明该含义在原句中完成什么交际动作。

它是**同步的语义解释路径**，不是自动的词源研究。必须区分：
- **Dictionary fact**：词典来源实际支持什么。
- **Sense selection**：当前语境为何选择其中一个义项，而非同词其他义项。
- **Semantic transition**：这个义项中的哪些成分，如何通过修饰、搭配、构词或固定表达形成新的表达意义。
- **Contextual interpretation**：当前句子究竟说了什么。
- **Pragmatic / practice inference**：这句话在活动中可能推动什么讨论或行动；这不反过来成为词典定义。

不得假定所有多义词都能从一个唯一“原始义”推导。不得把记忆类比伪装成历史词源。对习语、固定搭配、技术术语，必须按其证据类型选择路径，不能强行逐词推导。

## 3. 标准解释路径：六个连续步骤

| Step | 要回答的问题 | 必须留下的结果 |
|---|---|---|
| 1. Dictionary anchor | 这个词/组成部分在可靠来源中有哪些词性与常见义项？ | lemma、实际词形、POS、source sense、简明中文义 |
| 2. Contextual sense selection | 当前句子为什么选择这个义项？哪些相邻义项不适用？ | 明确选中义项与排除理由 |
| 3. Semantic decomposition | 被选义项内部强调什么？不是只抄一个中文对译 | 解释关键语义成分及其关系 |
| 4. Composition / transition | 它怎样与另一个词、词形或结构组合？组合后改变了什么？ | 从组成义到表达义的明确推导 |
| 5. Sentence interpretation | 在原句里具体是什么意思？句法、指称范围和承诺强度是什么？ | 忠于原句的完整解释 |
| 6. Language use | 说话者在做什么？哪些后续讨论可能自然发生？ | 交际动作、English Neighbors、适用表达；区分词义与实践推论 |

**连接规则**：每次从一个 Step 进入下一个 Step，都要有一个可读的“因为……所以……”关系。可以用箭头辅助，但箭头两端必须有解释，不能只画 A → B → C。

## 4. 完整示例：working definition

### 原句

*Let us agree on a working definition of a critical defect.*

学习例句：这是教学例句，不是客户原话，也不是正式质量标准。

### Step 1 — Dictionary anchor：先看 working 本身，不先背“暂时”

这里的 working 是形容词（adjective），不是动词 work 的进行时，也不是“正在工作的 definition”。

本次所用 OEWN 2025 义项为：

> **adopted as a temporary basis for further work**

项目中文教学摘要：**暂定用作进一步工作基础的**。

working 另有 *practical*（实用的）、*functioning*（正常运转的）、*operative*（供进一步工作或活动使用的）等形容词义项。它们不能混成一个含义。本句选择的是 *impermanent* 这一义项；不是说机器正常运转，也不是简单说“正在工作”。

### Step 2 — Contextual sense selection：为什么选“暂定工作基础”？

先拆开这个英文定义：

- **adopted**：被采用、被选来使用；重点是它已经被拿来作为一个依据，而不只是脑中一个想法。
- **a temporary basis**：一个现阶段使用的基础；它不是最终、永久的依据。
- **for further work**：它有实际用途，要让后续讨论、判断或工作可以继续。

因此，这个义项的重点不只是 *temporary*（时间短暂），而是：

> **一个被暂时采用、供后续工作据以展开的依据。**

从“暂时”单独跳到“工作定义”会丢掉 basis 和 further work 两个重要成分。真正连接到当前短语的是“暂时采用来作为工作依据”。

### Step 3 — Composition：为什么它能修饰 definition？

definition 是名词，指对一个词语、概念或对象含义的界定/说明。这里 *a definition of a critical defect* 不是在解释英语单词 critical，而是在界定“什么算作严重缺陷”。

working 是形容词，修饰 definition。它没有把 definition 变成“正在进行定义”，而是说明这个 definition 的**用途和当前地位**：

- definition 提供一个概念界定；
- working 把它限定为当前拿来使用、帮助后续讨论或判断的依据；
- 两者组合后，working definition 就是**现阶段供讨论、分析或分类使用的定义**。

所以中文可以译为“工作定义”“暂定定义”，更完整地说是“当前先采用、供进一步讨论和判断使用的定义”。

这里的“暂定”不是 working 在所有语境中的固定中文意思，而是本义项与 definition 组合后，对这个定义的当前状态所作的语境化表达。它可以以后修订，但不意味着一定会修订。

### Step 4 — Sentence interpretation：原句为什么这样使用？

*Let us agree on a working definition of a critical defect.*

可以理解为：

> 我们先就“严重缺陷”形成一个当前可供讨论和判断使用的定义。

推导关系是：

1. working definition 提供一个当前可用的定义；
2. of a critical defect 指明这个定义要界定的对象；
3. Let us agree on… 是提出共同约定的建议；
4. 因此说话者建议参与者先建立一个共同的判断口径，以便继续讨论。

注意：*Let us agree on* 是提议，不是报告“我们已经达成一致”；working definition 也不自动等于客户批准、正式质量标准或最终生效的验收准则。

### Step 5 — Contrast：为什么不直接用 tentative / provisional / final？

- **working definition**：强调这个定义目前被拿来作为工作的依据，重心在“当前可用”。
- **tentative definition**：强调尚未确定、仍带试探性，重心在“不确定”。
- **provisional definition**：强调暂行状态，常暗示等待进一步确认、条件满足或正式替代。
- **final definition**：强调已经定稿；与 working definition 的当前工作状态形成对照。

这些词在实际使用中可以有重叠，不是互斥分类。选择哪个词，要看说话者想强调“当前可用”“尚不确定”“等待确认”还是“最终定稿”。

### Step 6 — Language Game：这个表达让讨论可以继续做什么？

一旦团队提出 working definition，接下来的讨论可能包括：

- 哪些情况属于 critical defect？
- 哪些边界案例暂时无法判断？
- 当前分类需要哪些证据？
- 什么情况下需要修订这个定义？

这些是这个表达在质量讨论中可能引出的实践问题，不是 working definition 的词典定义，也不表示原句已经指定负责人或批准流程。

**Pragmatic Action**：这句话是在建议建立共同口径（align / establish a shared working basis），而不是宣布一个已经生效的标准。

**Workplace Use**：
- *Let's use this as a working definition for the current review.*  
  目前这次评审先按这个工作定义执行。
- *We can refine the working definition when more evidence is available.*  
  有更多证据后，我们可以进一步完善这个工作定义。

## 5. 可复用的内容模板

每个词条按类型选择适用路径，不要求机械套满所有项目。

### A. 单词（尤其多义词）

1. **Dictionary anchor**：lemma、实际词形、POS、常见义项与可靠来源。
2. **Sense selection**：指出本句选中哪一义，为什么；排除容易误选的义项。
3. **Semantic bridge**：解释被选义项的关键语义成分，以及它与当前用法之间真实存在的联系。
4. **Syntax & concept**：解释当前词形在句中承担什么作用，当前表达具体指什么。
5. **Contrast & neighbors**：只比较真正容易混淆的邻近表达。
6. **Language game & pragmatic action**：这句话在具体活动中完成什么动作，哪些后续问题自然相关。
7. **Use**：给一两个自然例句，明确自编或原文身份。

若两个词典义项之间没有可靠、自然的联系，直接说“这些是不同的常见义项；当前使用的是第X义”，不要虚构统一的原始意义。

### B. 组合词组（working definition 类型）

1. 先分别说明关键组成词的词典义项与词性。
2. 说明当前结构关系：中心词是什么，修饰词贡献什么。
3. 解释组成义如何组合成整体表达义；指出新增的状态、用途、范围或语气。
4. 说明当前句子如何进一步限定这个组合义。
5. 再分析 Contrast、Language Game、Pragmatic Action 与实际用法。

必须标明它是**词典收录的整词组**、**常见搭配**还是**根据组成词作出的语境组合解释**。不能把组件义项冒充整词组的词典释义。

### C. 固定习语 / 不透明短语

优先解释可靠词典中收录的**整体意义**，再说明句法结构和常见用法。若整体意义不能由组成词自然推出，不强行制造组合推导。

### D. 派生词 / 词形变化

从 lemma → morphology → POS/form → sentence role → contextual meaning 解释。词形相似不代表词性相同；不能把 -ing 一律解释成动名词或进行时。

### E. 工程技术表达

现实问题 → 中文技术概念 → 英文术语/词典依据 → 当前图纸/工艺/测量语境 → 实际工作表达。没有图纸、标准或产品证据时，明确限制，不虚构具体工程事实。

## 7. 独立 QA：Bridge 检查表

Reviewer 对每条候选解释检查：

- [ ] 所选词典义项、POS、lemma/form 与来源一致。
- [ ] 解释了为什么当前语境选择这个义项，而不是仅列出所有义项。
- [ ] 说明了从源义项到当前表达的中间步骤；没有直接从词典英文定义跳到最终中文短义。
- [ ] 组合关系准确（中心词、修饰关系、词性、习语/自由组合类型）。
- [ ] 每次语义变化都有理由；没有把相邻但不同的词典义项混为一个义项。
- [ ] 当前句子的解释忠于句法和语境，不扩大为原句没有表达的决定或承诺。
- [ ] Contrast、Language Game、Pragmatic Action 与前面的具体意义有关系，不是互不相干的栏目。
- [ ] 记忆类比未冒充词源；没有证据的语义关系明确写 N/A / no supported derivation。
- [ ] 自编例句、真实原句、工程事实和推断分别标明。
- [ ] 读者能用自己的话复述：词典依据是什么、为什么得到这个当前意思、在本句中起什么作用。

**失败标准**：即使所有段落单独正确，只要读者必须自己猜“为什么从 A 跳到 B”，Bridge QA 仍然 FAIL / REVISE。

## 8. 写作长度原则

语义链条要完整，篇幅不必很长。对普通工作词组，通常 4–6 个简短步骤或 4–5 个自然段足够。每一步只解释一个必要的语义转变；不重复整段词典义项，不机械复述所有词典义，也不为了填满模板创造虚假场景。

**最终验收问题：**读者能不能从可靠词典义项出发，一步一步看懂当前表达为什么是这个意思，而不是只记住一个中文翻译？
