# 七步分析系统：目标、要求与组装合同

状态：**规划交接，pending_build（待搭建）**。本文件于2026-11-16整理。本线程不生产七步内容、不启用七步运行器。一个GitHub主仓 `decidedtang-source/words-static`，七步作为M09独立模块管理。

## 1. 目标与边界

从已经摘出的真实原句出发，让读者理解当前词义、概念区别、语言活动和表达作用，最后能够迁移使用。七步是我们自己的原创分析系统；成熟词典、词史等资料仍由前部模块取得，不能用原创文字冒充抓取来源。

本模块只拥有七步正文、维度覆盖、关联实践、迁移表达和自己的展示区域。完整词典保留原接口，不在此线程抓取或改写。普通历史语用仍在M06；Bridge的折叠历史联系仍在M08；都不迁入M09。

场景不限项目工作，可来自采访、经济评论、讨论或真实工作。先解释原情境，最后明确转入教学性的工作迁移。以capacity为例，场景义可为“产能；可用资源所能支撑的工作量”；“现有资源不足以支撑两个项目启动”属于句子解释，不能替代词义。

## 2. 七步内容要求

| 顺序 | 维度 | 要完成的解释 |
| --- | --- | --- |
| 01 | Syntax／句法 | 找出影响理解的句子主干、词性、修饰、否定或条件，说明目标词在句中的位置。 |
| 02 | Concept／概念 | 解释这里指什么、范围和判断条件，增加信息，不重复场景义标签。 |
| 03 | Contrast／辨析 | 选择确实影响理解或表达选择的邻近词，说明什么条件下换用。 |
| 04 | Language Game／语言活动 | 解释当前活动、角色、问题、判断依据和什么回应切题，不统一套项目流程。 |
| 05 | English Neighbors／英文邻居 | 解释搭配、近反义、概念联系或典型追问为何相连，不只列词。 |
| 06 | Pragmatic Action／语用行动 | 解释说话者在限定、请求、澄清或提醒什么；区分句义、推断意图和实际发生的回应。 |
| 07 | Workplace Use／工作迁移 | 给2–5条自然的原创工作表达，附中文和使用条件；非工作原句的迁移明确标为新教学情境。 |

保留七维顺序，允许相邻维度合并成自然段。某维不必单独展开时，记录 `integrated` 和对应段落，或 `not_needed` 及简短理由；不填空段凑齐七栏。技术概念按现实问题→中文概念→英文术语→应用展开。“维特根斯坦式”仅指受语言使用与实践启发，不称为其本人固定七步程序。

共享Practice可引用零张、一张或多张。每词自身必须能读懂，实践卡不能替代本地解释。卡片独立保存ID、版本、角色、目标、依据、典型回应、边界和来源；只重建实际引用变更版本的词条。

## 3. 页面组装位置与区域

沿用原页面顺序：

```text
顶部原句来源折叠 → 词头／音标／发音 → 双义项导航
→ 完整词典（保留） → 高频义项与例句 → 普通历史语用
→ 场景原句／译文／重点／场景义
→ Bridge（现代联系 + 折叠历史联系）
→ M09 七步分析 #wl-deep
   01–06 连续分析正文（按需要合并小段）
   07 工作迁移表达／中文／适用条件
   可选：共享实践展开与来源链接
```

M09只能填充 `#wl-deep`，不能重复该ID、改动 `#wl-source` 或 `#wl-bridge`，不能把场景原句移到Bridge后面。入口沿用页内目录；可增加模块内部轻量锚点，回顶部仍指向 `#wl-top`。不增加悬浮球或强制切屏，不把七维变成七个同权重主导航。

手机版连续纵向阅读；平板、桌面继承现有宽度与导航。待搭建时保留同一锚点，仅显示“七步分析 · 待搭建”，不嵌入旧试产正文伪装新内容。这里是接入要求，当前文档提交没有修改现有页面实现。

## 4. 输入、输出及独立版本

规划接口在实施时落入 `word-page/modules/analysis/interface.v2.json`，不覆盖旧五区接口。

输入：`entryId`、`contextId`、原句与原句哈希、译文、场景义ID与解释、引用义项与来源、Bridge版本与输出哈希、原始Prompt版本与哈希、预设深度及理由、可选Practice版本。上下文不同须独立记录，不能只按拼写缓存。

输出：`moduleId: analysis`、接口／生产器／Prompt／内容版本、词条与语境ID、输入哈希、`status`、七维`coverage`、有稳定ID的正文`blocks`、`workplaceUse`（英文／中文／条件／原创标记）、`practiceRefs`、`sourceRefs`、内容量预算与实测、输出哈希。`coverage`通过block ID关联正文，避免重复存七份同文。来源引用指向具体事实或概念，不用一个词典链接为全部原创推断背书。

生命周期：`pending_build` → `draft` → `ready`；具体条目可为 `needs_expansion` 或 `blocked_input`。未搭建、缺输入、生成失败均保留真实状态，不用旧稿填充。状态不是用户接受或发布授权。

脚本只消费版本化模块产物，以 `entryId + contextId` 拼接；核对输入哈希、依赖版本和字段归属，拒绝串词或过期输入。M09更新不重抓词典或词史。输出写新批次目录，不覆盖旧冻结试样。

## 5. 内容量与QA

遵循当前 `config/qa/structure-flow-v1.1.json` 和 `docs/roadmap/v10/QA_CONTENT_AMOUNT_V1_1.md`：

| 预设档位 | 预计正文量 | 最低通过量 |
| --- | ---: | ---: |
| concise 简明 | 300–500 | 250 |
| standard 标准 | 600–900 | 500 |
| deep 深入 | 1000–1600 | 800 |

汉字按字、英文与数字按词计数；标题、元数据、引用资料、例句和译文不充当七步正文；完全重复段只计一次。工作表达至少2条双语另计。生产前决定档位，不因现稿短而降档。超量不截断；不足保留正文并列待补，不由QA自动凑字。

QA负责ID、字段、维度覆盖记录、引用、版本依赖、生产步骤、正文量、页面顺序、锚点和多屏。内容好坏由正常编辑与用户反馈改善，不设逐词反复语义评分或独立语义签字为生产门槛。旧R2文档要求此类门禁的部分已被用户后续决定替代；不能在新线程恢复。

前部试产中M09为 `not_in_scope / pending_build`，不判七步通过，也不因此阻断前部预览。前部完成与全系统完成分开报告。七步以后启用时再运行其结构和基础内容量检查，不修改旧QA冻结文件来绕过检查。
